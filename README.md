# Оценка идей и рекомендации

## 1: Аркада

### Концепция:

Аркадная игра, по сути один уровень - один вид паразита(то есть условно полный цикл жизни от яйца до организма-носителя)

**Плюсы:**
- Напрямую совпадает с образовательной целью - студент буквально проживает каждый этап цикла
- Модульность: новый паразит = новый уровень, легко расширять
- Соответствует ТЗ ("от первого лица")
- Разнообразие механик: на стадии церкарии - плаваешь, в ткани - уклоняешься от иммунитета, в кишечнике - закрепляешься
- Каждый уровень можно проверить с биологами по отдельности

**Минусы:**
- Риск однообразия, если механики не будут меняться между стадиями
- Нужно продумать геймплей для каждой стадии (а они очень разные)

## 2: Стратегия

### Концепция:

Стратегия (что-то похожее на plague inc.), где игрок управляет чем-то вроде колонии паразитов, выбирая различные особенности по мере развития, целью является успешно размножиться и не убить носителя

**Плюсы:**
- Залипательный геймплей
- Знакомый концепт, легко объяснить

**Минусы:**
- Стратегический слой **затмевает образовательный контент** - студент учится выигрывать, а не запоминать цикл
- Абстракция «колония» плохо ложится на реальную биологию конкретного паразита
- Значительно сложнее в балансировке
- Не учит конкретным стадиям жизненного цикла

## 3: гибрид аркады и графической новеллы с roguelite-элементами

### Концепция

Ты - паразит. Каждая «кампания» - один вид (описторх, малярийный плазмодий, токсоплазма, аскарида и т.д.). Геймплей разбит на **стадии жизненного цикла**, и каждая стадия - это **отдельная мини-игра + нарративная вставка**.

### Ключевые фишки(тут я плюсы и минусы еще не думал, поэтому чисто фишечки их в целом можно как плюсы расценивать)

- **Развилки с ошибками** - выбрал неправильного хозяина → гибель + объяснение. Это roguelite-подход: «умер - узнал - прошёл правильно»
- **Разные механики на каждой стадии** - не успевает надоесть
- **Нарративные вставки** - научный контент подаётся как история, а не как учебник
- **Финальная схема** - после прохождения студент видит полный цикл и может сопоставить его с тем, что прожил
- **Режим экзамена** - пройти цикл без подсказок, расставив стадии самостоятельно

## Технологии: тут ваще выбор выборов

### Вариант 1: **Godot Engine** (просто и со вкусом)

| Параметр | Оценка |
|---|---|
| Язык | GDScript (похож на Python), C# |
| 2D-возможности | Отличные |
| Экспорт в Web | Да (HTML5) - студенты открывают в браузере |
| Стоимость | Бесплатно, MIT-лицензия |
| Порог входа | Средний |
| Подходит для | Полноценная аркада с мини-играми |

**Основной прикол Godot:** экспорт в браузер = не нужно ничего устанавливать, GDScript похож на Python, отличная система сцен для модульной архитектуры (одна сцена = одна стадия).

### Вариант 2: **Ren'Py** (если упор на нарратив)

| Параметр | Оценка |
|---|---|
| Язык | Python + свой скриптовый язык |
| Специализация | Визуальные новеллы |
| Мини-игры | Можно встраивать через Python/PyGame |
| Экспорт | Windows, Mac, Linux, Web, Android |
| Порог входа | Низкий |

**Почему Ren'Py:** если команда сильна в контенте/арте, но слаба в программировании. Диалоги и развилки делаются за минуты. Мини-игры можно делать через встроенный Python.

### Вариант 3: **PyGame** (из ТЗ)

| Параметр | Оценка |
|---|---|
| Плюсы | Указан в ТЗ, чистый Python |
| Минусы | Нет готовой UI-системы, нет экспорта в web (без костылей), всё с нуля |
| Подходит | Если это жёсткое требование |

**Моё мнение:** PyGame - говно вариант, мы за два с копейками месяца мб и напишем основную логику, но выглядеть это будет не лучше чем игра в терминале через ASCII символы
